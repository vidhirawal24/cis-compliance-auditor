# BaselineGuard frontend handoff

Start here; product scope remains all 88 PRD IDs. This is independently testable
frontend work, not a claim of complete production/backend/device integration.

## Setup and safe configuration

Use Node 22.19+ and Corepack/pnpm (lockfile generated by pnpm 9.15.9):

```powershell
corepack pnpm --dir apps/web install --frozen-lockfile
corepack pnpm --dir apps/web dev:demo
```

`dev:demo` is explicitly synthetic and visibly labeled DEMO. Regular `dev` and the
production build read `/baselineguard-config.json` at startup. The committed
`apps/web/public/baselineguard-config.json` defaults to **disabled**, not fixtures.
An invalid/missing/unreachable configuration fails closed. Reload to apply a change.
No code change or secret is needed to configure deployment:

```json
{ "mode": "http", "apiBaseUrl": "/api/v1", "approvedReads": ["getReports"] }
```

`mode` is disabled, demo or http. Only an explicitly chosen demo mode enables
fixtures. The HTTP adapter currently binds only the guide's agreed GET `/reports`,
with the existing typed canonical envelope and runtime response validation. API
bases must be same-origin `/api/` paths; redirects and anonymous calls are refused.
It forwards a current Supabase access token to that same origin only. All remaining
methods, especially writes, reject as UNSUPPORTED. No HTTP error becomes DEMO data.
Enable a read only after the backend owner confirms the frozen payload contract.

Copy `apps/web/.env.example` only when configuring actual Supabase Auth. It contains
placeholders for **public URL and anon key only**. Do not use a service-role key,
device password, private key or privileged API token in browser configuration.
Live memberships/roles and MFA factor/challenge integration remain unresolved.
Real sessions are not assigned DEMO tenants/owner privileges. The local MFA example
works only in DEMO; real MFA is explicitly unsupported until integrated. Password
reset failure never becomes success or a DEMO delivery. Supabase is not contacted
when its public configuration is absent.

Legacy screen families 02-11 remain DEMO store-driven and reject production rendering.
Production plan/simulation/approval/verification bindings also remain incomplete.
The read adapter being configurable does not imply these screens are integrated.
Only backend authorization can grant access or execute an approved change.

## Checks

```powershell
corepack pnpm --dir apps/web lint
corepack pnpm --dir apps/web type-check
corepack pnpm --dir apps/web test
corepack pnpm --dir apps/web build
corepack pnpm --dir apps/web exec playwright install chromium
corepack pnpm --dir apps/web test:e2e
corepack pnpm --dir apps/web test:a11y
git diff --check
```

Playwright owns its DEMO Vite server on port 3000. Stop other servers on that port;
do not reuse an unknown server. On managed Windows, running browser tests may need
permission to start/stop child processes and access the browser cache. A sandboxed
first run stalled at teardown; direct Vite launch with adequate process permissions
completed normally. HTML reports/traces remain ignored under apps/web; captures in
the screenshot index are genuine DEMO browser evidence, not production results.
