19. Validation, constraints and implementation rules
• Never remove a requirement silently. All 38 mandatory entries and 50 extras stay in planned product scope; implementation status is
tracked per feature.
• No fake PASS states. Expose PASS, FAIL, NOT_APPLICABLE, MANUAL_REVIEW, ERROR and NOT_ASSESSED as distinct outcomes.
Report assessment coverage with compliance percentage.
• Device-specific compatibility. Vendors differ by appliance model, firmware and licensing. Maintain a collector/feature/command
compatibility matrix.
• Simulation is not proof. Batfish and custom models predict supported behavior; actual post-change checks remain required.
• No universal rollback guarantee. Backup, approval, supported device recovery and manual escalation are parts of the workflow.
• Benchmark rights matter. CIS content requires correct license/permission. OpenSCAP and other security content do not
automatically grant rights to bundle CIS Benchmarks.
• Real infrastructure authorization. Collectors and network discovery operate only against permitted devices/ranges, with least
privilege and audit logs.
• Security of the auditor itself. Privileged secrets remain in OpenBao; sensitive configuration artifacts use private access controls and
encryption.
• Pin and verify dependencies. Choose exact compatible library versions through integration testing; document unsupported features
and recovery paths.
