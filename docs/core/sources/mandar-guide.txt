remediations.

prompts.
10. A phase finishes only after code, tests, docs, and handoff artifacts are produced.

• Apoorva: use MSW or a typed in-memory adapter to render every screen and user journey while API is
unavailable.
• Mandar: use MockDeviceEngine implementing contract v1 until Vidhi package is installable.
• Vidhi: run a standalone CLI/fixtures and contract tests without importing Mandar API or Supabase.
• Contract changes: propose schema diff, review with all three, publish a minor version and only then
update consumers.
• Track M/E/I feature IDs in every phase, issue, pull request and acceptance test; full integration requires
evidence.

4. Frozen v1 contract - identical for all three
Read this carefully before giving any phase prompt to an AI coding IDE. It prevents three independently
generated projects from becoming incompatible.
CONTRACT v1.0.0 - FREEZE BEFORE INTEGRATION
Base HTTP prefix: /api/v1. Supabase Auth provides Bearer access token.
All API routes validate tenant membership/permissions on the backend.
Identifiers: org_id, asset_id, scan_id, finding_id, policy_pack_id,
plan_id, simulation_id, change_id, verification_id, report_id (UUID strings).
UTC timestamps: ISO 8601. Pagination: cursor + limit; filters in query params.
Status enum: PASS | FAIL | NOT_APPLICABLE | MANUAL_REVIEW | ERROR |
NOT_ASSESSED. EXCEPTION is a separate approval overlay, not fabricated PASS.
Simulation verdict: SAFE_IN_MODEL | VIOLATES_CONTRACT | UNSUPPORTED |
INSUFFICIENT_EVIDENCE. Execution states: DRAFT, SIMULATED, PRECHECKED,
PENDING_APPROVAL, APPROVED, EXECUTING, VERIFYING, VERIFIED, FAILED,
ROLLED_BACK, NEEDS_MANUAL_RECOVERY.
Canonical API error: {code, message, request_id, details?, retryable}.
Canonical resource envelope: {schema_version:'1.0.0', data, meta:{request_id}}.
Audit scores are server-computed: PASS/(PASS+FAIL); show assessed coverage.
Collector evidence must include asset_id, org_id, platform, vendor,
model, os_or_firmware_version, collector_version, collection_method,
collected_at, facts, evidence_refs[], supported_capabilities[],
unsupported_capabilities[], errors[]. Each evidence_ref has sha256 hash,
source command/API identity, encrypted artifact location and timestamp.
No raw passwords, keys, secrets, or privileged token contents in contracts.
Worker communication: JSON-serializable Pydantic commands/results; versioned.
Do not store free-form executable commands received from the browser.

Common integration order
• 1. Mandar exports contracts/v1 OpenAPI, Pydantic/JSON Schemas and sanitized fixtures; all three confirm
compatible signatures.
• 2. Vidhi installs device-engine as an editable Python package inside Mandar backend worker environment;
verify CLI and Pydantic contracts.
• 3. Mandar wires device jobs into Celery worker and checks evidence -> CIS evaluation -> findings/report
using fixture and lab outputs.

Critical acceptance gates
• 38 mandatory entries are covered by documented platform/control tests, including Windows 11/Server
2019, Ubuntu 20.04/22.04, RHEL 8/9, five firewall vendors, Cisco routers/switches.
• No unassessed or unsupported control is considered PASS. Benchmark mapping and licensing/source
provenance are visible.
• No privileged device command is sent without authorized scope, approved action, exact state
preconditions and safety checks.
• Simulation states and model coverage are truthful; actual service checks are separate from predicted
reachability.
• Four output formats (PDF/HTML/CSV/JSON) reconcile from the same canonical audit; reports contain
expected/actual/evidence/remediation.
• 88 scope remains retained, but completion status must be evidence-backed. An irreversible change uses
documented recovery, not fake rollback.
Handoff package - Mandar: owned directory; pinned dependencies; install/run commands; no-secret .env.example; contract
fixtures; test report; M/E/I evidence; known version limits; remaining integration questions.
